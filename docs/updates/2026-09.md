## U-20260923-09 · 2026-09-23 · Three email patterns made linear · #done #performance #security

- **What**: the email patterns in `pii_in_screenshot/scanner.py`, `pii_scanner/scanner.py` and `push_delivery/delivery.py` began with `\b`. On a long run of address characters with no `@`, for example digits separated by dots or dashes, `\b` holds before every digit, so the match restarted at each one and rescanned the rest: 2.4 s on 50 000 characters, about 45 s on 200 000. The OCR text, HAR bodies and push payloads they scan are page or app content, so a crafted page could stall a scan. They now start with `(?<![A-Za-z0-9._%+-])`, so a match can only begin where a run of address characters begins.
- **Found while** fixing the same pattern in LoadDensity's PII scrubber (LoadDensity U-20260923-16). The card patterns here, `\b(?:\d[ -]?){13,19}\b`, were measured and are already linear.
- **Behaviour**: ordinary addresses match exactly as before. The one difference is that an address glued to a leading `.`, `-`, `+`, `%` or `_` now includes that character, where the old pattern started after it.
- **Tests**: `test/unit_test/test_linear_text_scanning.py` +12: each pattern still finds addresses in three samples, and is linear on 200 000 characters with no `@` (fails on the old patterns, about 45 s each). The PII and push-delivery unit tests pass (94).
- **Files**: the three modules above, `test/unit_test/test_linear_text_scanning.py`.
- **Open items**: none.
