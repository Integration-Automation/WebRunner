## U-20261001-01 · 2026-10-01 · Dashboard stylesheet loads under its own CSP; escaping and 500 fixes · #change #dashboard #security

- **What**: fixes in the aggregated dashboard `je_web_runner/utils/live_dashboard/server.py` (`progress.md` #18, first stage).
  - Pages were unstyled: every response sends `Content-Security-Policy: default-src 'self'`, which blocks the inline `<style>` the pages carried. The stylesheet is now served from `/static/app.css` and linked from each page.
  - `_html_escape` escaped `& < > "` but not `'`, while the markup uses single-quoted attributes. It now calls `html.escape(quote=True)`.
  - A ledger without a `runs` key made `compute_flake_scores` raise `FlakeDetectorError`, which the loader did not catch (it caught `LedgerError`), so `/` and `/flake` answered 500. The loader now catches `WebRunnerException`.
  - A quarantine entry whose `flake_score` is not a number made `QuarantineRegistry` raise `ValueError`, which also became a 500. The page now shows the registry as empty and logs a warning.
- **Tests**: four new tests in `test/unit_test/test_live_dashboard_server.py` (`TestPageSafety`); all four fail on the previous code. The file passes (26 tests).
- **Files**: `je_web_runner/utils/live_dashboard/server.py`, `test/unit_test/test_live_dashboard_server.py`, `progress.md`.
- **Open items**: `progress.md` #18 (refactor, new UI, docs).

## U-20261001-02 · 2026-10-01 · MCP server: UTF-8 stdio, silent notifications, isError for tool failures · #change #mcp

- **What**: first stage of `progress.md` #21, the MCP server's protocol bugs (`je_web_runner/mcp_server/`).
  - stdio: `serve_stdio()` read and wrote with the console code page and CRLF line ends. With the default streams it now reads stdin as UTF-8 and keeps fd 1 for the protocol only (UTF-8, `\n`); the process's stdout, child processes included, is pointed at stderr. Before, `webrunner_scan_pii` on `"測試 alice@example.com"` under a latin-1 console reported the email at 7 instead of 3.
  - Notifications (messages without `id`) got error replies for unknown methods; they are now never answered.
  - Tool failures were JSON-RPC `-32000` errors carrying a Python `repr`. Now a handler that raises gives a result with `isError: true` and `"<ExceptionType>: <message>"`; an unknown tool or non-object `arguments` is `-32602`; a crash outside a tool is `-32603`.
  - `webrunner_run_actions` returned `isError: false` when actions failed, because the executor records failures instead of raising. The browser tools now call the new quiet `Executor.collect_action_results()`, add `failed` (the failed record keys; one list per file for `webrunner_run_action_files`) and set `isError` when any action failed. `record` keeps its shape.
  - A JSON array (batch) was expanded into separate replies; it is now rejected with one `-32600` error, as batching was removed in MCP 2025-06-18. A non-object message also gets `-32600` instead of silence.
- **Executor**: `execute_action()` now delegates to `collect_action_results(action_list) -> (record, failed)`, which does the same work without printing. `execute_action()`'s output and return value are unchanged.
- **Tests**: 7 new tests (`test/unit_test/test_mcp_server.py`, `test/integration_test/test_mcp_subprocess.py`), all failing on the previous code; the subprocess test pins the child's `PYTHONIOENCODING=latin-1` so the code-page bug reproduces on any machine. MCP, doc-count and the 279 executor/action unit tests pass.
- **Docs**: the MCP sections of `README.md`, `README/README_zh-CN.md`, `README/README_zh-TW.md` and `docs/source/{Eng,Zh}/doc/mcp_claude/mcp_claude_doc.rst` (result shape, error behaviour, stdout handling).
- **Open items**: `progress.md` #21 (version negotiation, tool metadata, security policy, 2026-07-28 era).
